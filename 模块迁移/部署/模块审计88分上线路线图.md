每一个二级菜单及专项批次必须同时满足：

## 1. 每批固定执行流程

1. **范围盘点**：建立一级菜单、二级菜单、页面、接口、表、流程、模板、角色矩阵。
2. **六维审计**：按安全、健壮性、架构、BladeX 规范、性能、质量逐项检查，所有发现必须定位到文件和行号。
3. **P0/P1 修复**：先清 P0，再清 P1；数据库、公开 API、流程节点等重大变更先记录决策。
4. **自动验证**：后端执行 `cd Boot && mvn clean compile -DskipTests`；表格 UI 有变更时执行 `cd saber3 && pnpm check:business-table-ui`。
5. **用户 UAT**：由用户使用真实角色、真实园区和真实业务数据完成页面与流程验证。
6. **重新评分**：按固定权重出具六维评分、剩余风险及上线结论。
7. **证据回填**：同步本路线图及《上线前验收清单》，记录接口、账号角色、样本数据和结果。
8. **批次停点**：状态改为“📦 待用户提交”，列出建议提交信息并停止；用户确认已提交后才进入下一批。

## 2. 分批实施计划

### 2.1 第 1 批：全局安全、权限、日志与流程基础

**状态**：⏸️ 用户要求暂缓  
**目标**：消除可影响全部业务模块的共性上线阻断项，为后续业务模块审计建立可信安全基线。

**范围（In）**：

- OAuth2/JWT、Token、参数签名、接口加解密及安全配置。
- dev/test/prod 环境中的数据库、Redis、OSS、Docker 仓库等敏感配置。
- 登录页默认账号密码及前端敏感信息。
- 通用接口权限、数据权限、多租户/园区隔离的代码基线。
- 关键写操作日志、异常日志和 Flowable 待办/身份映射基础。
- 安全部署说明、环境变量模板及必要的静态扫描规则。

**范围（Out）**：

- 各业务模块特有的字段、流程和 UI 整改，进入对应后续批次。
- 短信、邮件、小程序第三方渠道正式接入，进入第 9 批。
- 生产环境真实密钥写入仓库；仓库只保留环境变量引用和安全示例。

**任务清单**：

- [ ] **1-1 安全配置盘点**：定位硬编码密钥、默认密码、宽松开关、公开接口和日志缺口。
- [ ] **1-2 敏感配置治理**：生产/测试凭据改为环境变量注入，移除 POM 和前端默认凭据。
- [ ] **1-3 接口权限基线**：核验通用搜索、业务写接口及资源归属校验，修复明确越权点。
- [ ] **1-4 审计日志基线**：关键新增、修改、删除、审批、收付款操作具备可追溯日志。
- [ ] **1-5 流程身份基线**：核验 Flowable 待办按账号/角色可见，避免空待办和跨角色可见。
- [ ] **1-6 参数签名决策**：确定签名覆盖范围、兼容接口、前端签名能力和灰度启用方案。
- [ ] **1-7 自动验证与复评**：完成编译、静态扫描、六维复评并更新验收证据。
- [ ] **1-8 用户 UAT**：普通角色跨园区、跨角色、未授权接口和流程待办由用户真实验证。

**验收标准**：

- 仓库不再包含可直接使用的生产/测试数据库、Redis、OSS、Docker 仓库密码。
- 登录页不预填可用管理员密码。
- 非公开接口具有认证基线，关键资源访问校验租户/园区/角色归属。
- 关键业务写操作及异常可通过日志追踪到操作人、时间和业务主键。
- 参数签名有明确方案和生效范围，不以破坏文件上传、预览、下载和第三方回调为代价。
- 后端编译通过；本批综合评分达到 88 分硬门槛。

**当前已知风险**：

- `BladeConfiguration` 当前关闭参数签名，直接全局开启可能使旧前端、文件接口和回调接口失效。
- 历史配置中出现过真实测试/生产凭据，代码移除后仍需轮换已暴露凭据。
- 权限注解不能替代数据归属校验，后续仍需按模块用普通账号做越权复验。
