# 园区微信小程序完整开发方案

> 创建日期：2026-08-05  
> 实施状态：已完成  
> Spec：`.claude/blade-spec/park-miniapp/`

## 1. 建设目标

将 `miniprogram-3` 从本地 mock 原型升级为可连接现有 BladeX-Boot 4.9 的完整园区小程序。首版同时服务企业客户和园区管理员，形成企业提交申请、管理员处理、企业查看进度的闭环。

本期明确不开发 VR/在线看房、微信支付、真实门禁通行码和第三方服务商角色。

## 2. 总体架构

在 `Boot/src/main/java/org/springblade/modules/miniapp` 新增聚合模块，调用现有房源、客户、合同、账单、物业工单、增值服务和统计 Service。小程序只依赖 `/blade-miniapp` 接口，不直接使用 PC Controller 或 Entity。

接口分为四组：

- `/blade-miniapp/auth/**`：微信登录、手机号/邀请码绑定、刷新和退出。
- `/blade-miniapp/public/**`：首页、房源、物业服务、增值服务等游客接口。
- `/blade-miniapp/customer/**`：企业资料、看房、入驻、工单、合同、账单、成员。
- `/blade-miniapp/admin/**`：通知、工单处理、园区概览和租客详情。

## 3. 登录与权限

1. `wx.login` code 由后端调用微信 `jscode2session` 换取 OpenID。
2. 已绑定用户返回会话、租户、园区、企业、角色和能力集。
3. 未绑定用户通过微信手机号匹配现有管理员或企业联系人；不能唯一匹配时必须使用有效邀请码。
4. 角色固定为企业成员、企业管理员、园区管理员。
5. 每个保护接口都从服务端成员关系解析 `tenantId + parkId + customerId`，不采信客户端提交的企业与园区范围。

## 4. 数据库变更

- `biz_mini_member`：微信身份和业务身份绑定。
- `biz_mini_invite`：企业成员邀请码。
- `biz_mini_notification`：小程序站内通知。
- `biz_house_appointment`：看房预约。
- `biz_park_activity`：首页园区活动。
- `biz_business_opportunity`：补充来源房源、企业规模、预计入驻日期。

## 5. 业务范围

### 游客

- 浏览首页、政策、园区活动、公开房源、物业服务和增值服务。
- 房源列表和详情不包含 VR 字段或在线看房入口。

### 企业客户

- 提交看房预约、入驻意向、物业申请和增值服务意向。
- 查看和维护授权范围内的企业资料。
- 查看所属企业合同、账单、物业和增值服务工单。
- 企业管理员生成邀请码、管理企业成员。

### 园区管理员

- 查看和标记业务通知。
- 受理、派单、跟进、驳回和完成工单。
- 查看出租、收缴、工单概览及租客详情。

## 6. 小程序改造

- 新增统一请求、会话恢复、Token 刷新、权限守卫和集中服务层。
- 新增微信登录、手机号绑定和邀请码绑定页面。
- 页面优先使用真实接口，仅开发配置允许 mock 回退。
- 补齐 loading、空数据、错误重试和重复提交保护。
- 移除示例 logs 页面、在线看房入口和固定模拟通行码。
- 停车缴费首版作为物业服务申请，不产生真实支付结果。

## 7. 配置与安全

- 配置 `MINIAPP_WECHAT_APP_ID`、`MINIAPP_WECHAT_APP_SECRET`、默认租户和默认园区。
- AppSecret 不得写入仓库和小程序。
- 微信后台配置 HTTPS request 合法域名和隐私协议。
- 手机号、证照、合同附件按角色控制和脱敏。
- 提交接口使用请求号和 Redis 防止重复落库。

## 8. 验收

- 企业、管理员和游客三种访问路径符合权限预期。
- 跨企业、跨园区、篡改业务 ID 均无法读取或修改数据。
- 四类申请成功落库并生成管理员通知。
- 管理员处理后企业端展示最新状态和操作时间线。
- Token 失效、断网、空数据、服务错误有统一反馈。
- `mvn clean compile -DskipTests` 与 `npx tsc --noEmit` 通过。

## 9. 实施结果

- 后端已新增 `modules/miniapp` 聚合接口层、微信登录绑定、服务端权限上下文、业务闭环接口和数据库迁移脚本。
- 小程序已新增登录绑定、会话恢复、统一请求、单例 Token 刷新、权限守卫和真实 API 服务层，并完成主要页面接入。
- VR/在线看房、示例 logs 页面和固定模拟通行码已移除；停车缴费按物业服务申请处理。
- 后端 `mvn clean compile -DskipTests`、小程序 `npx tsc --noEmit`、JSON 格式、差异空白和范围外功能残留检查均已通过。

上线前仍需由部署环境完成真实微信 AppID/AppSecret、BladeX OAuth 客户端密钥、测试/生产 HTTPS API 域名、微信合法域名、Nginx 路由和数据库脚本执行，并使用微信开发者工具及真机完成企业/管理员双账号验收。
