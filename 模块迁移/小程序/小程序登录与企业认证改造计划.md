# 小程序登录与企业认证改造计划

> 制定日期：2026-08-27  
> 当前状态：方案已确认，待实施  
> 适用范围：`Boot`、`miniprogram-3`、`saber3`、小程序相关数据库迁移

## 1. 改造背景

当前小程序登录曾通过手机号匹配 `biz_customer.contact_phone`、后台用户和企业联系人，并据此自动判断企业身份。这种方式不能区分企业联系人、法定代表人和普通员工，也无法证明登录人确实属于该企业。

本次改造取消手机号推断身份，建立以下统一流程：

```text
微信登录并授权手机号
        ↓
创建或恢复小程序账号
        ↓
默认游客身份
        ↓
┌────────────────────┬────────────────────┐
│ 提交企业认证申请     │ 输入企业邀请码       │
│ Web 后台审核         │ 校验成功即时加入企业  │
└────────────────────┴────────────────────┘
        ↓
成为普通企业用户，自动归入用户管理的“租户”机构
```

## 2. 已确认的业务规则

### 2.1 小程序身份

小程序只保留两种业务身份：

- 游客：已完成微信登录和手机号授权，但未绑定企业。
- 企业用户：已通过企业认证，或通过有效企业邀请码加入企业。

小程序不设置园区管理员端，不设置企业管理员角色。园区工作人员继续在 Web 后台处理认证、企业、工单和其他管理业务。

### 2.2 手机号用途

- 手机号用于登录绑定、联系方式、后台查询和操作留痕。
- 手机号不能用于匹配 `biz_customer.contact_phone` 并自动获得企业身份。
- 手机号不能证明登录人是企业联系人、法定代表人或企业员工。
- 小程序账号以微信 OpenID、AppID 和已有 OAuth 绑定关系为主键恢复，不通过手机号自动合并任意 Web 后台账号。

### 2.3 企业认证

企业认证需要 Web 后台审核。申请字段以已确认页面为准：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 企业名称 | 是 | 最长 200 字符 |
| 是否个人 | 是 | 默认“否” |
| 联系人姓名 | 是 | 最长 100 字符 |
| 联系人手机号 | 是 | 使用微信授权手机号，只读 |
| 统一社会信用代码 | 条件必填 | 非个人申请必填 |
| 法定代表人 | 条件必填 | 非个人申请必填 |
| 注册资本（万元） | 否 | 非负数，最多两位小数 |

选择“是个人”时隐藏工商信息，不采集统一社会信用代码、法定代表人和注册资本。

本期不采集营业执照、身份证、邮箱、出生日期和性别。

### 2.4 企业员工加入

- 企业员工不提交待审核申请。
- 员工登录后只输入企业邀请码。
- 邀请码校验成功后立即加入对应企业。
- 后台只记录加入账号、企业、邀请码、手机号、加入时间和结果，不产生审核待办。
- 同一账号已加入同一企业时返回成功，不重复创建关系。
- 同一账号已属于其他企业时，不自动覆盖原关系，由 Web 后台先解除原企业关系后再加入新企业。

### 2.5 企业邀请码

- 一个企业同时只有一个有效邀请码。
- 企业认证审核通过时，若企业尚无邀请码，则自动生成一个邀请码。
- 企业已有有效邀请码时复用原邀请码，不重复生成。
- 邀请码归属于企业，不归属于个人。
- 企业认证申请人是邀请码接收人，但不会因此获得企业管理员权限。
- 邀请码只展示给对应认证申请人和有权限的 Web 后台人员，普通受邀员工不展示邀请码。
- Web 后台可以停用或重新生成邀请码；重新生成后旧邀请码立即失效。
- 邀请码采用不可推测的随机 8 位大写字母和数字，排除 `0/O`、`1/I` 等易混字符。
- 接口日志、错误信息和普通列表默认不完整输出邀请码。

### 2.6 历史数据

- 不删除现有测试账号。
- 不清空历史登录、成员关系或业务记录。
- 不删除已经创建的小程序相关表。
- 不通过重建数据库实现本次改造。
- 迁移脚本必须可重复执行，并兼容已经执行过部分旧脚本的数据库。
- 历史 `mini_customer_admin` 关系继续可登录，但权限按普通企业用户处理；后续新增关系统一写入 `mini_customer_member`。

## 3. 身份、组织和权限模型

### 3.1 各数据层职责

| 数据层 | 职责 |
| --- | --- |
| `blade_user` | 账号主体，用于在 Web 用户管理中统一查询和停用账号 |
| `blade_user_dept` | 用户管理中的“游客/租户”机构归类 |
| `blade_user.role_id` | Web 后台菜单角色，不作为小程序企业权限依据 |
| `blade_user_park` | Web 园区工作人员的数据范围，不用于识别小程序企业用户 |
| `blade_user_oauth` | 微信 OpenID 与账号绑定 |
| `biz_mini_member` | 小程序成员、手机号、当前身份和当前企业上下文 |
| `biz_mini_customer_member` | 小程序成员与正式企业客户的有效关系 |
| 企业认证申请表 | 企业认证内容和后台审核记录 |
| 企业邀请码表 | 企业唯一有效邀请码及接收人 |
| 企业加入记录表 | 邀请码加入的审计记录 |

### 3.2 用户管理归类

首次登录完成后：

- `blade_user.user_type` 使用小程序外部用户类型。
- 用户归入“游客”机构。
- 分配无 Web 菜单权限的小程序游客角色，避免继续使用含义不清晰的 `role_id = -1`。
- 分配专用“小程序用户”岗位，或在用户管理中将岗位显示为“不适用”，不授予后台岗位权限。

企业认证通过或邀请码加入成功后：

- 将小程序外部账号从“游客”移动到“租户”。
- 将 Web 角色设置为已有的零菜单权限“企业用户（`corp`）”。
- 同步更新 `blade_user.dept_id` 和 `blade_user_dept`。
- 创建或激活 `biz_mini_customer_member` 企业关系。
- 更新 `biz_mini_member.customer_id`、`park_id` 和 `role_code`。

上述“移动到租户”仅用于账号管理和分类，不授予 Web 后台登录权限。小程序企业数据权限只认有效的 `biz_mini_customer_member`。

### 3.3 Web 后台账号保护

- 新微信用户不能仅因手机号相同而自动绑定已有 `UserType.WEB` 账号。
- 园区后台工作人员的部门、角色和 `blade_user_park` 不得被小程序身份流转覆盖。
- 如果授权手机号已被 Web 账号使用，小程序手机号仍保存在 `biz_mini_member`；用户管理列表可关联显示该手机号，但不强行覆盖 `blade_user.phone` 的唯一约束。

## 4. 数据库设计

### 4.1 保留并调整 `biz_mini_customer_member`

保留 `65_add_miniapp_customer_member_scope.mysql.sql`，因为 `biz_mini_customer_member` 是企业用户权限的核心关系表，物业工单和增值服务工单的 `member_id` 个人范围索引也仍然需要。

实施时调整脚本和代码语义：

- 表注释从“手机号授权”调整为“小程序企业成员关系”。
- 新增关系的 `role_code` 固定为 `mini_customer_member`。
- 手机号只保留为关系快照，不再触发自动授权。
- 增加 `join_source`：`CERTIFICATION`、`INVITE`、`ADMIN`。
- 增加可选的 `certification_id`、`invite_id` 和 `join_time`，用于追溯来源。
- 新增成员维度唯一约束，防止同一成员重复加入同一企业。
- 保留现有历史迁移和工单 `member_id` 回填，不删除已有数据。
- 删除代码中的 `customerMatches(mobile)` 自动匹配逻辑，而不是删除该关系表。

如果 `65.sql` 已经在数据库执行，删除文件也不会删除数据库表，因此不能通过删除脚本解决旧逻辑问题。

### 4.2 企业认证申请表

建议新增 `biz_mini_enterprise_certification`：

| 字段 | 说明 |
| --- | --- |
| `id`、`tenant_id` | 主键和租户 |
| `member_id`、`user_id` | 申请人 |
| `mobile` | 申请时手机号快照 |
| `enterprise_name` | 企业名称 |
| `is_individual` | 是否个人 |
| `contact_name` | 联系人姓名 |
| `credit_code` | 统一社会信用代码 |
| `legal_representative` | 法定代表人 |
| `registered_capital` | 注册资本（万元） |
| `customer_id` | 审核确认的企业客户 |
| `park_id` | 审核确认的企业所属园区 |
| `status` | `PENDING`、`APPROVED`、`REJECTED`、`CANCELLED` |
| `review_remark` | 审核意见 |
| `review_user`、`review_time` | 审核人和审核时间 |
| 基础审计字段 | 创建、更新、删除标记 |

约束：

- 同一成员同一时间只能有一条待审核申请。
- 非个人申请校验企业名称、信用代码和法定代表人。
- 审核通过必须选择一个有效的 `biz_customer`。
- 不根据申请内容自动创建签约租户企业。
- 重复审核必须幂等，不重复创建成员关系或邀请码。

### 4.3 企业邀请码表

建议新增 `biz_mini_enterprise_invite`：

| 字段 | 说明 |
| --- | --- |
| `id`、`tenant_id` | 主键和租户 |
| `customer_id`、`park_id` | 对应企业和园区 |
| `invite_code` | 唯一邀请码 |
| `receiver_member_id` | 企业认证申请人，即邀请码接收人 |
| `status` | 启用或停用 |
| `version` | 重置次数或版本 |
| `generated_time` | 生成时间 |
| 基础审计字段 | 创建、更新、删除标记 |

数据库保证一个企业最多一条有效邀请码，邀请码全局唯一。

### 4.4 企业加入记录表

建议新增 `biz_mini_enterprise_join_log`：

- 记录成员、用户、手机号、企业、园区和邀请码记录 ID。
- 记录 `SUCCESS`、`INVALID_CODE`、`DISABLED_CODE`、`ALREADY_JOINED`、`CONFLICT` 等结果。
- 记录请求时间和必要的设备/来源信息。
- 不记录完整微信 code、access token 或 AppSecret。
- 加入失败记录只用于安全审计，不改变用户企业关系。

## 5. 后端改造计划

### 5.1 微信登录

1. 使用 `wx.login` code 换取 OpenID。
2. 根据 `tenant_id + app_id + open_id` 查找 `biz_mini_member`。
3. 新用户授权手机号后创建独立小程序账号并归入“游客”。
4. 已有用户根据有效企业成员关系重算身份。
5. 不再查询 `biz_customer.contact_phone` 推断企业。
6. 不再自动生成 `mini_customer_admin`。
7. 不再因手机号相同自动合并任意 Web 用户。
8. 登录、刷新和资料接口统一从服务端有效关系生成能力集。

### 5.2 企业认证接口

小程序侧建议接口：

- `GET /blade-miniapp/member/enterprise-certification/latest`：查询最新申请和状态。
- `POST /blade-miniapp/member/enterprise-certification`：提交申请。
- `POST /blade-miniapp/member/enterprise-certification/{id}/cancel`：撤销待审核申请。
- `GET /blade-miniapp/member/enterprise-invite`：认证申请人查询本企业邀请码。

Web 侧建议接口：

- `GET /blade-park/mini-certification/page`：认证申请分页。
- `GET /blade-park/mini-certification/detail`：认证详情。
- `POST /blade-park/mini-certification/{id}/approve`：选择企业并通过。
- `POST /blade-park/mini-certification/{id}/reject`：驳回并填写原因。

### 5.3 邀请码加入接口

建议接口：

- `POST /blade-miniapp/member/enterprise/join`：输入邀请码并加入企业。
- `GET /blade-miniapp/member/enterprise/join-result`：查询当前企业关系。
- `GET /blade-park/mini-invite/page`：后台查询企业邀请码。
- `POST /blade-park/mini-invite/{customerId}/regenerate`：重新生成。
- `POST /blade-park/mini-invite/{customerId}/disable`：停用。
- `GET /blade-park/mini-invite/join-logs`：查询加入记录。

接口增加限流、错误次数控制和重复提交保护，防止邀请码被批量猜测。

### 5.4 企业认证审核通过事务

审核通过必须在同一个事务内完成：

1. 锁定待审核申请，防止重复审核。
2. 校验后台选择的企业有效且审核人有对应园区权限。
3. 创建或激活 `biz_mini_customer_member`，角色固定为普通企业用户。
4. 更新 `biz_mini_member` 的企业、园区和身份。
5. 将小程序外部账号移动到“租户”机构并分配 `corp` 零菜单角色。
6. 为企业获取或创建唯一有效邀请码。
7. 将邀请码接收人设置为本次认证申请人。
8. 将申请更新为已通过并记录审核人、时间和意见。
9. 使旧小程序会话失效或提升身份版本，确保下一次请求获得新权限。

任意一步失败时全部回滚，不能出现“申请已通过但没有企业权限”的半完成状态。

### 5.5 邀请码加入事务

1. 规范化邀请码并进行限流校验。
2. 锁定并校验邀请码、企业和园区状态。
3. 检查成员是否已属于其他企业。
4. 创建或激活 `biz_mini_customer_member`。
5. 更新 `biz_mini_member` 当前企业和普通企业用户身份。
6. 将小程序外部账号移动到“租户”并分配 `corp` 角色。
7. 写入企业加入记录。
8. 刷新或重新签发小程序 Token，前端无需退出重登即可进入企业功能。

## 6. 小程序改造计划

### 6.1 我的页面

根据身份展示：

- 游客：显示“企业认证”和“加入企业”入口。
- 企业认证待审核：显示当前状态和提交时间，仍可使用游客公共功能。
- 企业认证已驳回：显示驳回原因和重新申请入口。
- 企业用户：显示企业名称和认证状态，不再显示重复认证入口。
- 企业认证申请人：额外显示“企业邀请码”查看和复制入口。

### 6.2 企业认证页面

- 保持当前小程序背景和整体视觉。
- 按已确认截图分为“基本信息”和“工商信息”。
- 手机号自动带出且不可编辑。
- “是否个人”为“是”时隐藏工商信息。
- 表单校验在 TypeScript 中完成，不在 WXML 中堆叠复杂判断。
- 提交按钮增加 loading 和防重复提交。

### 6.3 加入企业页面

- 页面仅保留企业邀请码输入框和确认按钮。
- 不要求再次填写姓名、手机号、邮箱、身份证、生日或性别。
- 校验成功后展示企业名称，并立即刷新登录身份。
- 无效、已停用、已重置和企业冲突分别给出明确提示。

### 6.4 权限边界

游客可访问全园区公共能力：

- 首页公共内容。
- 全部启用园区的公开房源。
- 政策、活动、通知和公开服务。
- 看房预约和入驻意向等个人提交功能。
- 企业认证和邀请码加入。

企业用户在游客能力基础上增加：

- 所属企业资料。
- 所属企业合同和账单。
- 本人提交的企业工单和服务记录。
- 明确授权的其他企业私有数据。

公共内容可以跨园区浏览；企业私有数据始终按有效企业关系隔离，不能因公共接口全局开放而放开合同、账单和工单。

## 7. Web 后台改造计划

### 7.1 企业服务菜单

在现有“企业服务”一级菜单下新增：

- 企业认证审核：认证申请列表、详情、通过和驳回。
- 企业邀请码：企业、邀请码状态、接收人、生成时间、停用和重新生成。
- 企业加入记录：建议作为“企业邀请码”页面中的标签页，不额外增加菜单层级。

新增菜单同步配置到企业服务顶部菜单，并继承企业服务已有角色；审核、查看、重置邀请码分别使用独立菜单权限。

### 7.2 企业认证审核页面

- 使用 `basic-container`、统一查询区、工具栏、带边框表格和右侧分页。
- 支持按企业名称、联系人、手机号、申请状态和申请时间筛选。
- 状态使用 `el-tag`：待审核蓝色、已通过绿色、已驳回红色、已撤销灰色。
- 操作列固定右侧，提供“查看”和“审核”。
- 审核通过必须选择一个有效企业客户，自动显示该企业所属园区。
- 审核驳回必须填写原因。

### 7.3 用户管理增强

用户管理继续作为所有小程序账号的最终管理入口，增加或关联展示：

- 小程序身份：游客或企业用户。
- 所属企业。
- 企业所属园区。
- 认证/加入来源。
- 微信绑定状态。

支持按“游客/租户”、企业名称和手机号查询。停用用户时，小程序登录和 Token 刷新必须同步失效。

## 8. 旧逻辑移除范围

实施时移除或停用以下行为：

- `MiniAuthServiceImpl.customerMatches(mobile)`。
- 根据 `biz_customer.contact_phone` 创建企业授权关系。
- 自动分配 `mini_customer_admin`。
- 企业管理员专属能力和成员管理入口。
- 小程序园区管理员入口及对应管理能力。
- 员工认证待审核流程。
- 邀请码页面中的身份证、邮箱、出生日期和性别字段。

保留已有微信 AppID/AppSecret 配置、Token 刷新修复、OAuth 历史兼容、公共房源范围和并发 401 跳转修复。

## 10. 验收场景

### 10.1 登录和游客

- 新手机号首次登录后出现在“用户管理 > 游客”。
- 即使手机号等于企业联系电话，也不会自动成为企业用户。
- 游客可以查看全部园区公开房源、政策和活动。
- 游客访问合同、账单和企业工单时被服务端拒绝。

### 10.2 企业认证

- 非个人申请缺少信用代码或法定代表人时不能提交。
- 个人申请不显示也不校验工商信息。
- 待审核和驳回状态不会获得企业权限。
- 审核通过后用户自动出现在“用户管理 > 租户”。
- 审核通过后企业关系、园区和能力集一致。
- 同一申请重复点击通过不会产生重复关系或多个邀请码。

### 10.3 企业邀请码

- 审核通过后企业只有一个有效邀请码。
- 认证申请人可以查看邀请码，普通受邀员工不能查看。
- 正确邀请码使游客即时成为对应企业用户，无需审核。
- 无效或停用邀请码不会改变用户身份。
- 重置后旧邀请码失效，新邀请码可正常加入。
- 已属于其他企业的用户不能直接切换企业。
- 每次尝试均产生不包含敏感凭据的加入记录。

### 10.4 历史兼容

- 当前测试账号可以继续登录。
- 现有 `biz_mini_customer_member` 关系继续有效。
- 历史 `mini_customer_admin` 按普通企业用户能力运行。
- 已有工单的 `member_id` 和个人查询范围不丢失。
- 迁移脚本重复执行不报错、不重复插入、不清空数据。
