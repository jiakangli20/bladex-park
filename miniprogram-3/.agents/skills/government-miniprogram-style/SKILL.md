# 政企小程序 UI 交付规范

将小程序改造为克制、可信、清晰、可持续维护的政企服务界面。此 Skill 同时约束页面框架、视觉样式、WXML/WXSS 实现、图片图标和交付验收；不得只做颜色替换，也不得破坏业务流程、事件绑定、状态语义和可点击区域。

## 必须执行的工作方式

1. 先检查 `app.wxss`、公共组件、目标页面 WXML/WXSS、页面配置和当前渲染器。
2. 明确页面服务的角色、首屏主任务、关键业务状态和当前改造范围。
3. 先确定页面框架，再修改组件和样式；先修改全局外壳与公共组件，再改造具体页面。
4. 修改后必须执行类型检查、UI 审计和 Skyline 预览。存在未解决错误时不得宣称完成。
5. 任务要求交付时，必须同时给出改造范围、检查结果、页面截图清单和已知例外。

## 页面框架

每个页面只能选用以下一种框架，不得混用。

| 页面类型 | 适用场景 | 固定结构 |
| --- | --- | --- |
| 任务页 | 列表、表单、详情、申请 | 紧凑页头 → 上下文或筛选 → 主列表/表单 → 必要时固定底部操作 |
| 身份页 | 我的、通行凭证、企业资料 | 企业身份信息 → 分组业务行 → 底部导航 |
| 运营页 | 管理端概览、待办、统计 | 标题和更新时间 → 核心指标 → 待办事项 → 下钻列表 |

页面首屏必须说明“当前位置”和“用户当前能完成什么”。主任务必须先于公告、活动、营销内容出现。功能内容使用正常文档流，不得依赖负边距、卡片叠压、绝对定位或图片背景才能被阅读和点击。

## 视觉令牌与布局

| 角色 | 值 | 使用规则 |
| --- | --- | --- |
| 品牌蓝 | `#1D4E89` | 主操作、选中态、关键链接 |
| 深品牌蓝 | `#163D6C` | 按下态、深色页头强调 |
| 页面底色 | `#F5F7FA` | 页面背景 |
| 内容表面 | `#FFFFFF` | 卡片、固定操作区 |
| 控件底色 | `#F1F4F7` | 搜索、未选中标签、进度轨道 |
| 边框 | `#E5EAF0` | 卡片和列表行边界 |
| 主文字 | `#1F2937` | 标题、关键数值 |
| 次文字 | `#5F6B76` | 说明、标签 |
| 弱文字 | `#7B8794` | 元信息、未选中控件 |
| 成功 | `#2F7D5A` / `#EAF4EE` | 已完成、正常 |
| 警示 | `#A86A15` / `#FFF6E5` | 待处理、需关注 |
| 风险 | `#B64545` / `#FCEEEE` | 逾期、驳回、错误 |

- 页面左右边距固定为 `32rpx`，区块间距 `24rpx`，卡片内部间距 `16rpx`。
- 卡片圆角 `8–12rpx`，优先使用 `1rpx` 边框，不使用装饰性阴影。
- 列表行点击高度 `96–112rpx`；主按钮高度不小于 `72rpx`；紧凑图标操作区不小于 `64rpx`。
- 一个页面只使用一种品牌蓝。服务分类、快捷入口和菜单不得用彩虹色区分。
- 禁止营销式渐变、玻璃拟态、超大圆角、大面积悬浮控件和营销化文案。

## 通用组件规范

| 组件 | 必须包含 | 限制 |
| --- | --- | --- |
| 区块 | 标题 → 可选说明/次操作 → 一个内容分组 | 同一内容不得同时使用卡片和散列列表两种样式 |
| 列表行 | 前置标识 → 标题/数值 → 可选状态 → 箭头 | 状态必须有文字，不能只用颜色 |
| 服务入口 | 图标或文字标识 → 任务名称 → 可选说明 | 使用中性品牌风格，不按服务类别上色 |
| 信息卡片 | 标题 → 核心字段 → 可选辅助信息/操作 | 白底、边框、无装饰阴影 |
| 标签/筛选器 | 文字 → 选中态 | 选中态统一使用品牌蓝和文字/边框变化 |
| 固定底部操作 | 单一主操作 → 安全区 | 同屏不得有两个同权重主按钮 |
| 空状态 | 当前无数据说明 → 可选下一步 | 不使用夸张插画或营销口号 |

## 文案、状态与可用性

- 标题说明“是什么”，按钮说明“要做什么”，状态说明“当前处于什么阶段”。
- 使用“提交申请、查看进度、待处理、已完成、暂无法办理”等明确表达，避免“立即体验、火热办理、尊享服务”。
- 关键业务信息不得仅靠颜色、图标或页面位置表达；风险、逾期、驳回、未读数量必须有文字或数字。
- 长企业名称、合同号、时间、金额和房间号在 375px 宽度下必须可识别；不得出现横向滚动或主按钮被遮挡。
- 每个操作组件必须具备默认、按下、禁用、加载/提交中状态；表单还必须提供必填和错误提示。

## Skyline 实现约束

以下实现禁止用于功能性 UI：

- CSS `mask`、`mask-image`、`-webkit-mask` 及相关定位、重复、尺寸属性。
- WXSS 中的 `data:image/...`，包括内联 SVG。
- `filter`、`backdrop-filter`。
- 仅依赖 CSS 伪元素显示图标、操作、状态或业务数据。

替代方式：

- 功能图标使用具有固定尺寸和 `mode` 的本地 `<image>`；暂未提供资产时，使用可读的短文字标识。
- 业务图片使用 `<image>`，必须声明 `src`、`mode` 和用于定义宽高的 class；不得作为背景图。
- 有业务意义的图片和图标不得 `display: none`、降低 `opacity` 或被装饰层遮挡。
- 返回/前进使用可见文字或不依赖伪元素的边框箭头。

## 检查与交付门禁

在项目根目录执行类型检查，并使用 Skill 目录中的审计脚本：

```bash
npx tsc --noEmit
node <Skill目录>/scripts/audit-wxss.mjs <项目目录>/miniprogram --strict
```

严格审计会阻断：CSS mask、内联 data-image、滤镜等 Skyline 风险实现；也会将渐变、阴影、大圆角、负边距和缺失图片属性列为必须清零的发布问题。

同时在微信开发者工具 Skyline 模式中，以 375px 宽度检查：首页、服务页、我的页、一个管理端页面；并验证至少一条看房、物业申请、企业服务申请、个人中心查询和管理端工单处理路径。

## 交付输出

每次正式交付必须提供：

1. 改造页面与影响组件清单。
2. 视觉/框架改造说明及业务语义影响说明。
3. `npx tsc --noEmit` 与严格 UI 审计输出。
4. Skyline 页面截图：首页、服务页、我的页、管理端页。
5. 关键路径测试记录。
6. 已知限制及例外清单；未经业务方、产品负责人和技术负责人确认的例外不得交付。

## 完成标准

只有当页面框架、视觉令牌、组件实现、图片图标可见性、类型检查、严格审计和 Skyline 预览全部满足本 Skill 时，才可标记为“可交付”。
