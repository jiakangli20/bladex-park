# 园区管理小程序开发指南

本项目是一个面向园区企业客户与园区管理员的微信小程序。PC 端已存在，移动端优先承接高频、轻量、现场化的业务：企业客户看房、提交申请、查看合同与缴费事项；管理员接收通知、处理工单、查看园区运行概览。

## 项目定位

- 小程序端不是 PC 端的完整搬运，优先服务移动场景。
- 企业客户侧以“找房、办事、查状态”为核心。
- 管理员侧以“收提醒、处理工单、看概览”为核心。
- 数据来源以后应接入现有 PC 端接口；当前页面原型使用 `miniprogram/utils/mock.ts` 中的本地 mock 数据。

## 技术栈与目录

- 原生微信小程序：WXML / WXSS / TypeScript。
- 入口配置：`miniprogram/app.json`。
- 全局样式：`miniprogram/app.wxss`。
- 页面目录：`miniprogram/pages/*`。
- 公共组件：`miniprogram/components/*`。
- mock 数据：`miniprogram/utils/mock.ts`。
- 静态图片：`miniprogram/assets/images/*`。

当前已存在页面：

- `pages/index/index`：首页。
- `pages/houses/index`：我要看房。
- `pages/services/index`：企业服务，包含物业服务和增值服务 tab。
- `pages/service-detail/index`：增值服务详情。
- `pages/mine/index`：用户中心。

## 用户角色

### 企业客户

企业客户是小程序的主要使用者，包含已入驻企业和潜在入驻企业。

核心能力：

- 查看园区房源。
- 提交看房预约和入驻意向。
- 发起物业服务申请。
- 查看和采购增值企业服务。
- 查看企业信息、合同、租金、缴费记录、工单状态。

### 园区管理员

管理员负责处理企业客户在小程序端发起的申请，并查看园区运营情况。

核心能力：

- 接收客户入驻、物业申请、增值服务申请、逾期缴费等通知。
- 处理物业工单。
- 处理增值服务工单。
- 查看园区概览、租客企业信息和租赁详情。

### 服务商或运营人员

如后续存在第三方服务商，可作为增值服务的履约主体。

核心能力：

- 查看被分配的增值服务申请。
- 更新服务进度。
- 反馈办理结果。

## 功能模块拆解

### 1. 我要看房

目标：提供企业客户查看园区房源信息，并支持线上登记入驻意向。接入三方平台后，支持在线看房。

页面建议：

- 房源列表：搜索、园区筛选、租金筛选、楼层筛选、更多筛选。
- 房源详情：图片、面积、价格、楼层、装修、标签、可租状态、房源介绍。
- 预约看房：联系人、手机号、意向时间、企业名称、备注。
- 入驻意向：意向面积、行业类型、预计入驻时间、企业规模、需求说明。
- 在线看房：三方 VR / 视频看房链接入口。

关键数据：

- 房源 ID、楼宇、楼层、门牌、面积、租金、物业费、状态。
- 房源图片、标签、朝向、装修、可租时间。
- 看房预约记录、入驻意向记录。

### 2. 物业服务

目标：开放企业用户在小程序端查看与发起物业管理服务。

首批业务：

- 水电缴纳。
- 车位申请。
- 维修申请。
- 投诉建议。
- 会议室预订。

页面建议：

- 物业服务入口页。
- 服务申请表单页。
- 我的物业工单列表。
- 工单详情与进度页。

关键状态：

- 待提交、待受理、处理中、待评价、已完成、已取消。

### 3. 企业服务 / 增值服务

目标：提供企业查看和采购各类增值企业服务。

首批分类：

- 工商服务。
- 财税代理。
- 知识产权。
- 法律服务。
- 政策申报。
- 人才招聘。

页面建议：

- 增值服务列表：分类、搜索、服务卡片。
- 服务详情：服务说明、服务商、评价、申请人数。
- 填写意向：企业联系人、联系电话、需求说明。
- 我的增值服务申请：申请状态和处理进度。

关键状态：

- 已申请、待受理、沟通中、服务中、已完成、已关闭。

### 4. 用户中心

目标：企业客户在小程序端查看和维护企业信息，并查看合同、租金等入驻相关事项。

页面建议：

- 我的首页：企业认证状态、房间信息、待办数量。
- 企业信息：企业名称、统一社会信用代码、联系人、行业、规模。
- 我的合同：合同列表、合同详情、合同附件查看。
- 租金缴纳：应缴账单、逾期账单、缴费记录。
- 我的工单：物业工单和增值服务工单统一入口。
- 账号管理：手机号、微信绑定、成员管理。

权限边界：

- 企业普通成员只能查看与自身企业相关的数据。
- 企业管理员可维护企业资料、查看合同和缴费记录。

### 5. 通知管理

目标：对管理员进行业务提醒。

通知类型：

- 客户入驻申请。
- 看房预约。
- 物业服务申请。
- 增值服务申请。
- 逾期缴费。
- 工单超时。

页面建议：

- 通知中心列表。
- 通知详情。
- 待办入口，可直接跳转到对应工单或申请。

关键字段：

- 通知类型、业务 ID、标题、内容、接收角色、已读状态、创建时间。

### 6. 物业工单处理

目标：管理员在小程序端处理企业客户申请的物业服务。

页面建议：

- 物业工单列表：按状态、类型、紧急程度筛选。
- 工单详情：申请企业、房间、联系人、问题描述、图片附件。
- 处理动作：受理、派单、更新进度、完成、驳回。
- 评价查看：企业评价与反馈。

关键状态：

- 待受理、已受理、已派单、处理中、已完成、已驳回。

### 7. 增值服务工单处理

目标：管理员在小程序端处理企业客户申请的增值服务。

页面建议：

- 增值服务申请列表。
- 申请详情。
- 指派服务商。
- 跟进记录。
- 完结服务。

关键状态：

- 待受理、已指派、服务中、已完成、已关闭。

### 8. 园区概览

目标：展示园区总体运行情况以及各租客企业信息和租赁详情。

页面建议：

- 运营概览：首页数据看板。
- 招租概览：总面积、可租面积、出租率、待租房源数。
- 收缴概览：本月应收、已收、逾期金额。
- 工单概览：待处理、处理中、超时、已完成。
- 租客列表：企业名称、所在楼宇、合同周期、缴费状态。

管理员端优先展示轻量数据，不建议在小程序里做复杂报表。

## 推荐开发优先级

### 第一阶段：企业客户闭环

先让企业客户能用起来。

1. 首页。
2. 我要看房列表与详情。
3. 看房预约 / 入驻意向表单。
4. 物业服务入口和申请表单。
5. 增值服务列表、详情、意向提交。
6. 用户中心：企业信息、我的工单、合同和缴费记录入口。

### 第二阶段：管理员处理闭环

让管理员能处理企业提交的事项。

1. 通知中心。
2. 物业工单列表、详情和处理动作。
3. 增值服务工单列表、详情和处理动作。
4. 逾期缴费提醒。

### 第三阶段：园区运营概览

沉淀管理驾驶舱能力。

1. 园区概览。
2. 租客企业列表。
3. 租赁详情。
4. 招租、收缴、工单统计。

## 建议接口清单

命名仅作前后端对齐参考，实际以 PC 端已有接口为准。

### 企业客户端

- `GET /api/mini/houses`：房源列表。
- `GET /api/mini/houses/{id}`：房源详情。
- `POST /api/mini/house-appointments`：提交看房预约。
- `POST /api/mini/settlement-intentions`：提交入驻意向。
- `GET /api/mini/property-services`：物业服务类型。
- `POST /api/mini/property-work-orders`：提交物业工单。
- `GET /api/mini/value-services`：增值服务列表。
- `GET /api/mini/value-services/{id}`：增值服务详情。
- `POST /api/mini/value-service-orders`：提交增值服务意向。
- `GET /api/mini/profile/company`：企业信息。
- `GET /api/mini/profile/contracts`：合同列表。
- `GET /api/mini/profile/bills`：租金和缴费记录。
- `GET /api/mini/profile/work-orders`：我的工单。

### 管理员端

- `GET /api/mini/admin/notifications`：通知列表。
- `POST /api/mini/admin/notifications/{id}/read`：标记已读。
- `GET /api/mini/admin/property-work-orders`：物业工单列表。
- `GET /api/mini/admin/property-work-orders/{id}`：物业工单详情。
- `POST /api/mini/admin/property-work-orders/{id}/actions`：处理物业工单。
- `GET /api/mini/admin/value-service-orders`：增值服务工单列表。
- `GET /api/mini/admin/value-service-orders/{id}`：增值服务工单详情。
- `POST /api/mini/admin/value-service-orders/{id}/actions`：处理增值服务工单。
- `GET /api/mini/admin/overview`：园区概览。
- `GET /api/mini/admin/tenants`：租客企业列表。
- `GET /api/mini/admin/tenants/{id}`：租赁详情。

## 数据权限建议

- 小程序登录应绑定微信 openId / unionId 与系统用户。
- 企业客户只能访问所属企业、所属房间、所属合同和所属工单。
- 管理员接口必须校验管理员角色。
- 管理员可按园区、楼宇、工单类型、服务类型进行数据隔离。
- 合同、账单、企业证照等敏感信息应按角色控制字段可见性。

## 开发约定

- 新页面放在 `miniprogram/pages/<module>/index.*`。
- 公共组件放在 `miniprogram/components/<component-name>/`。
- 接口接入前，统一在 `miniprogram/utils/mock.ts` 维护 mock 数据。
- 接口接入后，建议新增 `miniprogram/services/`，按业务模块封装请求。
- 不要在页面 WXML 中写复杂业务判断，状态组装优先放在 TS 文件中。
- 样式以当前蓝色主视觉为主，保持移动端信息密度适中。
- 按钮、卡片、状态标签应优先复用全局样式或已有页面写法。
- 不要把管理员端和企业客户端混在同一个复杂页面里；可以按角色显示入口，但业务页面应保持边界清晰。

## 验证方式

当前项目没有完整构建脚本。修改 TypeScript 后至少执行：

```bash
npx tsc --noEmit
```

页面效果需要使用微信开发者工具预览。重点检查：

- 页面是否已配置到 `miniprogram/app.json`。
- 底部导航跳转是否正确。
- 长文本是否溢出。
- 表单输入和提交提示是否符合业务语义。
- 管理员入口是否有清晰的角色权限判断。
