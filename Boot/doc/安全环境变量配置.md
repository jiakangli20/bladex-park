# BladeX 园区系统安全环境变量配置

测试和生产环境不得把数据库、Redis、OSS、OAuth2 私钥、Token 密钥或镜像仓库密码写入 Git。敏感值由部署平台、系统服务配置或密码管理器注入；配置文件只保留变量引用。

## 必填变量

| 变量 | 用途 | 要求 |
| --- | --- | --- |
| `BLADE_OAUTH2_PRIVATE_KEY` | 登录密码 SM2 解密私钥 | 与前后端公钥配套，禁止复用已泄露密钥 |
| `BLADE_TOKEN_SIGN_KEY` | Token 签名 | 随机生成，至少 32 位 |
| `BLADE_DB_PASSWORD` | 业务数据库密码 | 至少 12 位，不使用默认口令 |
| `BLADE_REDIS_PASSWORD` | Redis 与分布式锁密码 | 至少 12 位，不与数据库共用 |
| `BLADE_OSS_ACCESS_KEY` | OSS/MinIO 访问账号 | 使用业务专用账号 |
| `BLADE_OSS_SECRET_KEY` | OSS/MinIO 访问密钥 | 至少 12 位，按环境隔离 |

启用 Token 加密、超级密钥或接口报文加密时，还需分别设置 `BLADE_TOKEN_CRYPTO_KEY`、`BLADE_SUPER_KEY_CRYPTO_KEY`、`BLADE_API_AES_KEY` 和 `BLADE_API_DES_KEY`。Docker 构建使用 `DOCKER_USERNAME`、`DOCKER_PASSWORD`；生产接口文档默认关闭，只有显式设置 `BLADE_OPENAPI_ENABLED=true` 才会开放。

## 本地启动

本地开发使用 `dev` 配置时，先在当前终端导入本地专用凭据，再启动后端。不要把实际值写入本文档或提交到 `.env`：

```bash
export BLADE_OAUTH2_PRIVATE_KEY='<本地SM2私钥>'
export BLADE_TOKEN_SIGN_KEY='<本地Token签名密钥>'
export BLADE_DB_PASSWORD='<本地数据库密码>'
export BLADE_REDIS_PASSWORD='<本地Redis密码，可为空时不设置>'
export BLADE_OSS_ACCESS_KEY='<本地MinIO账号>'
export BLADE_OSS_SECRET_KEY='<本地MinIO密钥>'
mvn spring-boot:run
```

前端只有在启用对应加密能力时才设置 `VITE_BLADE_TOKEN_CRYPTO_KEY`、`VITE_BLADE_API_AES_KEY` 和 `VITE_BLADE_API_DES_KEY`。浏览器端变量会进入构建产物，不能视为服务端机密。

## 上线要求

1. 测试、生产使用不同凭据，且不得沿用仓库历史中出现过的值。
2. 测试和生产 profile 启动时会校验关键变量；缺失、长度不足或使用常见弱口令将拒绝启动。
3. 变更密钥后同步更新 OAuth2 公私钥、前端公钥和部署平台配置，并执行登录、刷新 Token、上传下载和流程审批复验。
4. 凭据轮换只通过运维渠道完成，日志、截图、验收文档和提交信息均不得记录明文。
